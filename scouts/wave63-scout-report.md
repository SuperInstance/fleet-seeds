**1. Turbo Harness: Instance-Adaptive Harness Optimization — [arXiv:2609.40330](https://arxiv.org/abs/2609.40330)** (2026-09-30). *Claim*: a single globally-optimized harness is never optimal per task instance; existing RSI harness search wastes this. *Mechanism*: after a global harness-optimization run completes, recycle its artifacts into a structured **profile** per instance, then use a learned planner to pick/adapt the harness configuration for each new instance at negligible extra search cost. *Fleet test*: the lode engine seals one global candidate config per run; instead, ship run-artifacts (prior scores, exclusion history) into a per-lane harness overlay and pre-register "instance-adaptive vs global" as the run-8 A/B. **2. Learning from Research: Toward Lifelong Agent Harness Evolution (ScholarEvo) — [arXiv:2609.40169](https://arxiv.org/abs/2609.40169)** (2026-09-30). *Claim*: meta coding agents that modify harnesses from their own execution feedback are reactive and exploration-poor; human experts read the literature. *Mechanism*: a research-mining stage converts papers into structured, actionable harness patches before the coding agent mutates anything. *Fleet test*: the fleet already mines (M1–M12); the missing artifact is the **structured patch object** — register "mine → candidate harness-patch (file, function, claim, falsifier)" as a first-class engine output, then measure patch-acceptance vs free-text mining notes. **3. CollabFlow: Recursive Self-Improvement of Agent Collaboration — [arXiv:2609.38662](https://arxiv.org/abs/2609.38662)** (2026-09-29). *Claim*: multi-agent RSI loops stay open — collaboration is fixed by operators, topology-only learning propagates verbatim errors, and reward maximization collapses onto a few teams. *Mechanism*: a trainable **Collab-Director** constructs teams of complete agents per task, a **frozen verifier** scores outcomes, and outcomes retrain the director across tasks. *Fleet test*: wardroom threads + wave queues are collaboration traces; pre-register a director that composes lanes per wave from the registry's outcome rows, with the seal-discipline as the frozen verifier. **4. Rep2Skill: Representation-Guided Skill Self-Evolution for LLM Agents — [arXiv:2609.39149](https://arxiv.org/abs/2609.39149)** (2026-09-30). *Claim*: skill libraries evolve from long text trajectories and sparse outcomes, leaving the agent's internal representations outside the optimization loop. *Mechanism*: reflect on **internal representations** (execution-state embeddings) to diagnose and rewrite external textual skills. *Fleet test*: quilt-jepa latents are the fleet's native representation stream — test whether garden skill updates driven by jepa-latent reflection beat trajectory-only rewrites on the same task bank (two-arm pre-registration, M3 hold-out cell reserved).
